§0 · Onboarding methods & the matrix

Every database is onboarded by one (or more) of three methods. Which apply depends on the engine and whether it's self-managed or a managed cloud service.

  • Agent — taps the connection on the DB host. Modes by MODE: network (passive wire, plaintext), host (eBPF below TLS), inline proxy (in-path, can block). Gives exact row counts. MySQL & PostgreSQL only — host mode hooks OpenSSL, which SQL Server (SChannel) and Oracle (libnnz) don't use, and Mongo wire-decode is low-value.
  • AgentLite (audit-forward) — reads the database's native audit source (log or telemetry) and forwards it. Works for every engine. Detective only (no blocking); MySQL/PG have no row counts this way.
  • PaaS (agentless) — a managed cloud DB routes its native audit into a cloud stream (Pub/Sub, Kinesis, Event Hub) or blob that DAM consumes. No install on the DB.

🐬 MySQL / MariaDB port 3306

Prerequisites

  • Version: MySQL 5.7 / 8.x, MariaDB 10.x.
  • Agent host: Linux x86-64. For Agent & AgentLite the agent runs on the DB host.
  • Egress: outbound HTTPS 443 from the host to your DAM control plane.
  • Token: a per-workspace enrollment token (§ token) and the instance registered by its private IP.
  • (Optional) read-only login for classification / VA — runs on the DB VM, so scope it to loopback:
CREATE USER 'dam_svc'@'127.0.0.1' IDENTIFIED BY '<strong-secret>';
GRANT SELECT, PROCESS ON *.* TO 'dam_svc'@'127.0.0.1';
FLUSH PRIVILEGES;

Agent — network / host

Tap the wire for row counts. Pick by transport (pre-checks on the DB VM):

# ① plaintext or TLS? empty cipher = plaintext (network); a cipher = TLS (host)
mysql -e "SELECT t.processlist_user usr, COALESCE(NULLIF(s.variable_value,''),'(plaintext)') tls
  FROM performance_schema.status_by_thread s JOIN performance_schema.threads t ON t.thread_id=s.thread_id
  WHERE s.variable_name='Ssl_cipher';"
# ② TCP or socket? Host='localhost' = unix socket (invisible to network mode); 'ip:port' = TCP
mysql -e "SELECT SUBSTRING_INDEX(host,':',1) src, count(*) FROM information_schema.processlist GROUP BY 1;"
# ③ interface carrying 3306 (use 'any' if unsure)
sudo ss -Htnp state established '( sport = :3306 )' | awk '{print $4"  <-  "$5}'

Install (network shown; for host use MODE=host — needs kernel ≥5.8 + BTF + the DB on TLS):

sudo tee /etc/toovix/agent-network.env >/dev/null <<EOF
MODE=network            # or host
DB_ENGINE=mysql
TARGET_HOST=127.0.0.1   # reachable DB address (also the instance identity)
TARGET_PORT=3306
CAPTURE_IFACE=any
AGENT_ENROLL_TOKEN=tvxenr_...
CONTROL_PLANE=https://dam.yourcompany.com
EOF
sudo systemctl enable --now dam-agent@network
Plaintext → network, TLS → host. Network can't read TLS; host captures nothing on a plaintext DB. Deploy both on a mixed-transport DB (no double-counting). For blocking, use MODE=proxy (in-path).

AgentLite — general query log

Detective, no row counts. Enable the general log to a file, then run the forwarder on the DB host:

mysql -e "SET GLOBAL log_output='FILE'; SET GLOBAL general_log_file='/var/log/mysql/general.log'; SET GLOBAL general_log='ON';"
# persist in my.cnf (Debian: /etc/mysql/mysql.conf.d/  ·  RHEL: /etc/my.cnf.d/): general_log=1, log_output=FILE
# agent env: MODE=audit-forward DB_ENGINE=mysql AUDIT_SOURCE=general_log AUDIT_LOG=/var/log/mysql/general.log TARGET_PORT=3306

Full per-engine detail: AgentLite setup guide.

PaaS — RDS / Aurora / Cloud SQL (agentless)

No install. Turn on the managed audit and route it to a stream DAM consumes:

  • RDS / Aurora MySQL: enable the MARIADB_AUDIT_PLUGIN / server audit → publish to CloudWatch Logs → a Kinesis stream the DAM connector reads.
  • Cloud SQL (MySQL): enable audit → Cloud Logging sink → Pub/Sub topic → dam-audit-consumer.
PaaS carries no row counts for MySQL. Coordinate with your DAM operator — they own the stream name and run the consumer.

🐘 PostgreSQL port 5432

Prerequisites

  • Version: PostgreSQL 12+.
  • Agent host: Linux x86-64, on the DB host for Agent & AgentLite.
  • Egress: outbound HTTPS 443.
  • (Optional) read-only login for classification / VA:
CREATE ROLE dam_svc LOGIN PASSWORD '<strong-secret>';
GRANT pg_monitor TO dam_svc;                 -- settings/stats for VA; NO write
-- per target database (\c yourdb):
GRANT CONNECT ON DATABASE yourdb TO dam_svc;
GRANT USAGE ON SCHEMA public TO dam_svc;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO dam_svc;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO dam_svc;
The agent dials TARGET_HOST for classification, and it runs ON the DB VM — so use a locally-reachable address (usually 127.0.0.1 or the private IP the DB listens on; check sudo ss -tlnp | grep 5432). A public IP the DB isn't listening on gives connection refused. Any pg_hba.conf rule you add is for the agent's source IP, never the DAM control-plane IP.

Agent — network / host

Pre-checks on the DB VM:

# ① plaintext? (want ssl=f for network; ssl=t → host mode)
sudo -u postgres psql -x -c "SELECT a.usename, a.client_addr, s.ssl
  FROM pg_stat_activity a LEFT JOIN pg_stat_ssl s ON s.pid=a.pid WHERE a.backend_type='client backend';"
# ② TCP vs unix-socket (an IP = TCP; NULL = socket → AgentLite)
sudo -u postgres psql -c "SELECT COALESCE(host(client_addr)::text,'unix-socket') src, count(*)
  FROM pg_stat_activity WHERE backend_type='client backend' GROUP BY 1;"
# ③ interface for 5432 (host mode also: uname -r ≥5.8, /sys/kernel/btf/vmlinux, grep libssl /proc/$(pgrep -x postgres|head -1)/maps)
sudo ss -Htnp state established '( sport = :5432 )' | awk '{print $4"  <-  "$5}'
sudo tee /etc/toovix/agent-network.env >/dev/null <<EOF
MODE=network            # or host (TLS DB)
DB_ENGINE=postgresql
TARGET_HOST=127.0.0.1
TARGET_PORT=5432
CAPTURE_IFACE=any
AGENT_ENROLL_TOKEN=tvxenr_...
CONTROL_PLANE=https://dam.yourcompany.com
EOF
sudo systemctl enable --now dam-agent@network
Host mode is TLS-only. If the DB is plaintext but you want host mode: create a server cert/key in the data dir (chmod 600 server.key), ALTER SYSTEM SET ssl='on' + reload, then move the app to sslmode=require.

AgentLite — statement log

sudo -u postgres psql -c "ALTER SYSTEM SET log_statement = 'all';"
sudo -u postgres psql -c "ALTER SYSTEM SET log_line_prefix = '%m [%p] %u@%d ';"   -- the parser needs this exact prefix
sudo -u postgres psql -c "SELECT pg_reload_conf();"
# agent env: MODE=audit-forward DB_ENGINE=postgresql AUDIT_SOURCE=pgaudit AUDIT_LOG=/var/log/postgresql/postgresql-16-main.log

PaaS — RDS / Cloud SQL / Azure (agentless)

  • RDS PostgreSQL: enable pgaudit → CloudWatch Logs → Kinesis → connector.
  • Cloud SQL (Postgres): pgaudit / log → Cloud Logging → Pub/Sub → dam-audit-consumer (Cloud SQL emits structured protos, not text).
  • Azure Database for PostgreSQL: pgaudit → diagnostic setting → Event Hub → connector.

🪟 SQL Server port 1433

Prerequisites

  • Version: SQL Server 2017+.
  • Collector host: any Linux x86-64 host that can reach <db>:1433 — nothing is installed on Windows (the agent polls over TDS).
  • Login: a SQL login with VIEW SERVER STATE (Extended Events) or CONTROL SERVER (SQL Server Audit). Classification reuses the same read-only login.

Agent — network / host

Not available for SQL Server. Host mode hooks OpenSSL, but SQL Server encrypts with Windows SChannel — there's no libssl to attach to, and there's no on-host wire agent for Windows. Use AgentLite below (it even gives row counts via Extended Events).

AgentLite — Extended Events / Audit (TDS poll)

Pick a source, then run the Linux collector. Extended Events adds row counts; Audit gives cleaner object-level scoping.

-- Extended Events (row counts):
CREATE EVENT SESSION ToovixXE ON SERVER
  ADD EVENT sqlserver.sql_statement_completed
    (ACTION(sqlserver.server_principal_name, sqlserver.client_hostname, sqlserver.database_name)
     WHERE [sqlserver].[database_name]=N'YourDB')
  ADD TARGET package0.event_file (SET filename=N'C:\SQLAudit\ToovixXE.xel', max_file_size=50, max_rollover_files=5)
  WITH (MAX_DISPATCH_LATENCY=5 SECONDS, STARTUP_STATE=ON);
ALTER EVENT SESSION ToovixXE ON SERVER STATE = START;   -- START, not ON
GRANT VIEW SERVER STATE TO [dam_svc];
# collector env (any Linux host reaching 1433):
MODE=audit-forward DB_ENGINE=mssql AUDIT_SOURCE=xevents (or sql_server_audit)
TARGET_HOST=<sqlserver-addr> TARGET_PORT=1433 DB_USER=dam_svc DB_PASSWORD=…
on-prem: AUDIT_LOG='C:\SQLAudit\ToovixXE*.xel'

PaaS — Azure SQL (agentless / collector)

  • Extended Events → Blob (recommended — carries row counts): create the session ON DATABASE to a blob target; the same xevents collector reads it over TDS from inside the VNet. Set MSSQL_XE_SESSION=ToovixXE, omit AUDIT_LOG (the agent follows blob rollover). Principal action is sqlserver.username on Azure SQL.
  • SQL Auditing → Event Hub (fully agentless, no row counts): database-level auditing routed to an Event Hub the DAM connector consumes.

DDL + full setup: AgentLite guide § SQL Server.

🅾️ Oracle port 1521

Prerequisites

  • Version: Oracle 19c / 23ai (unified auditing on).
  • Collector host: any Linux host reaching <db>:1521 — nothing installed on the DB host. Covers VM, RDS and OCI Autonomous DB.
  • Login:
CREATE USER dam_svc IDENTIFIED BY "<strong-secret>";
GRANT CREATE SESSION TO dam_svc;
GRANT AUDIT_VIEWER TO dam_svc;          -- reads UNIFIED_AUDIT_TRAIL
GRANT SELECT_CATALOG_ROLE TO dam_svc;   -- V$SQLSTATS (row counts) + ALL_TAB_COLUMNS (classify)

Agent — network / host

Not available for Oracle. Oracle Net encrypts with its own library (libnnz), not OpenSSL, so eBPF host mode can't hook it, and there's no supported on-host wire agent. Use AgentLite — it polls the unified audit trail and recovers row counts from V$SQLSTATS.

AgentLite — Unified Audit Trail (SQL*Net poll)

CREATE AUDIT POLICY toovix_dml ACTIONS SELECT, INSERT, UPDATE, DELETE;
AUDIT POLICY toovix_dml EXCEPT dam_svc;   -- so the poller doesn't audit its own reads
# collector env: MODE=audit-forward DB_ENGINE=oracle AUDIT_SOURCE=unified_audit_trail
TARGET_HOST=<oracle-addr> TARGET_PORT=1521 ORACLE_SERVICE=<service> DB_USER=dam_svc DB_PASSWORD=…

PaaS — RDS Oracle / OCI Autonomous DB

Same unified-audit collector — it runs anywhere reaching 1521.

  • OCI Autonomous DB: set is_mtls_connection_required = false and add the collector's IP to the ADB access-control list; the agent connects over one-way TLS, no wallet. ORACLE_SERVICE is the long *.oraclecloud.com name. Oracle-maintained internal SQL is dropped automatically.
  • RDS Oracle: enable unified auditing; point the collector at the RDS endpoint.

🍃 MongoDB port 27017

Prerequisites

  • Version: MongoDB 4.4+.
  • Collector host: any Linux host reaching <db>:27017 — covers Atlas and remote mongod.
  • Login: least-privilege — not dbAdmin (which can drop collections):
use yourdb
db.createRole({ role:'toovixProfiler', privileges:[{ resource:{db:'yourdb',collection:''}, actions:['enableProfiler'] }], roles:[] })
use admin
db.createUser({ user:'dam_svc', pwd:'<strong-secret>', roles:[
  { role:'clusterMonitor', db:'admin' }, { role:'read', db:'yourdb' }, { role:'toovixProfiler', db:'yourdb' } ] })

Agent — network / host

Not available for MongoDB. There's no OpenSSL-based below-TLS hook and wire-decode is low-value. Use AgentLite (the database profiler).

AgentLite — database profiler (poll)

use yourdb
db.setProfilingLevel(2, { slowms: 0 })     // every op; persist in mongod.conf → operationProfiling.mode: all
# collector env: MODE=audit-forward DB_ENGINE=mongodb AUDIT_SOURCE=profiler
TARGET_HOST=<mongo-addr> TARGET_PORT=27017 DB_NAME=yourdb DB_USER=dam_svc DB_PASSWORD=…
system.profile is capped (best-effort, not a guaranteed trail) and find reports only its first batch — set MONGO_INCLUDE_GETMORE=true for true read volume. Classification isn't supported for Mongo (schemaless).

PaaS — MongoDB Atlas

Same profiler collector — supply an Atlas connection string and run it anywhere that reaches the cluster:

# collector env for Atlas:
MODE=audit-forward DB_ENGINE=mongodb AUDIT_SOURCE=profiler DB_NAME=yourdb
MONGO_URI='mongodb+srv://dam_svc:…@cluster.xxxxx.mongodb.net/'  TARGET_HOST=<cluster>  (identity)

Common — for every engine

Enrollment token & instance

In the console: Agents → Deploy monitoring → pick the method → copy the tvxenr_… token + control-plane URL. Register the database with its private IP (unique per DB) — that's how DAM identifies the instance and where optional classification connects.

Install the binary (self-managed hosts)

# Debian/Ubuntu: curl -fsSL $CP/api/download/dam-agent_amd64.deb -o a.deb && sudo dpkg -i a.deb
# RHEL/Rocky/Alma/OL: curl -fsSL $CP/api/download/dam-agent_amd64.rpm -o a.rpm && sudo dnf install -y ./a.rpm
# systemd unit is templated: dam-agent@<name> reads /etc/toovix/agent-<name>.env
Classification & VA attach to any method: add CLASSIFY=true and/or VA_SCAN=true with DB_USER/DB_PASSWORD/DB_NAME and restart — no reinstall. VA runs read-only CIS checks (MySQL/PG/SQL Server/Oracle); it isn't required to install the agent.
